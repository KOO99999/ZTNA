# 행동 신호 오프라인 평가 (night_access / unknown_location)

실제 사용자 기록이 없어, 행동 기반 신호(평소 아닌 시간·나라)는 **공개 데이터셋 2개**로 탐지율과 오탐률을 측정했다.
공격 기반 신호(WAF, 위협 IP, 기기, 세션 나라 변경)는 실측 날 통제된 반복 시험으로 따로 측정한다.

| 파일 | 내용 |
|---|---|
| `rba_eval_results.json` | RBA 데이터셋 채점 결과(`tools/rba_eval.py`) |
| `cert_eval_results.json` | CERT r4.2 채점 결과(`tools/cert_eval.py`) |

## 공통 방법
- 로그인을 **시간순으로** 하나씩 넘기며, **그 시점까지의 기록만** 보고 엔진과 같은 규칙으로 판정한다(미래를 보지 않음).
- 공통 규칙: 22~06시면 야간, 회사 나라가 아니면 위치 이상.
- 개인 기준(엔진 기본값): 지난 30일 기록이 10건 이상이면, 지금 시각 앞뒤 1시간 비율 < 5%면 평소 아닌 시간, 지금 나라 비율 < 5%면 평소 아닌 나라. 10건 미만이면 공통 규칙.
- 정답 표시와 맞춰 탐지율(공격 중 잡은 비율)과 오탐률(정상 중 잘못 걸린 비율)을 낸다.
- 민감도: 기록 최소 건수(5/10/20) × 비율 기준(2/5/10%) × 시간 폭(앞뒤 0/1/2시간) 27개 조합.

## 1. RBA 데이터셋 (Wiefling et al., ACM TOPS 2022, CC BY 4.0)
- 실제 대형 온라인 서비스 로그인을 바탕으로 만든 데이터. 파일 전체 31,269,264줄을 읽음.
- 판정 대상(로그인 성공): 12,541,442건 = 정상 11,736,887 / 공격 IP 성공 804,415 / **계정 탈취 140**
- 가정: 실패한 로그인은 판정하지 않음(엔진은 비밀번호 통과 뒤 판단), 계정 탈취 로그인도 이력에 들어감(보수적),
  회사 나라 = 데이터에서 가장 많은 나라(NO), 시각은 Europe/Oslo 현지 시각.

**배점 근거 다시 재기(정상 로그인 기준)**

| | 예전(앞 300만 건, UTC 0~5시) | 이번(전체, 현지 22~06시) |
|---|---|---|
| 야간 발생률 | 10.75% | 13.44% |
| 처음 보는 나라 발생률 | 0.52% | 0.71% |
| 희귀도(-log2) 비율 나라 : 야간 | 2.4 : 1 | **2.47 : 1** (30일 기준 2.45 : 1) |

현재 배점 비율(40 : 20 = 2 : 1)과 가깝다 → 배점 유지.

**채점(신호가 하나라도 켜진 비율)**

| | 계정 탈취 탐지 | 정상 오탐 |
|---|---|---|
| 공통 규칙 | 95.0% | 35.6% |
| 개인 기준 | 95.7% | 34.3% |

전체로는 차이가 작다. 정상 로그인 중 개인 기준이 실제로 작동한 비율이 6.6%뿐이기 때문(이 서비스 사용자 대부분은 한 달에 10번 미만 로그인).

**기록이 충분한 사용자(30일 10건 이상, 정상 776,331건)만**

| | 공통 규칙 | 개인 기준 |
|---|---|---|
| 정상 오탐(신호 하나라도) | 29.0% | **8.9%** |
| 정상 오탐 - 나라 | 21.6% | 0.2% |
| 정상 오탐 - 시간 | 11.0% | 8.7% |
| 공격 IP 성공 로그인 탐지 | 68.9% | 27.6% |
| 계정 탈취 탐지 | 2/3 | 3/3 (표본 3건, 결론 불가) |

해석: 매일 접속하는 사용자에게 개인 기준은 오탐을 약 3분의 1로 줄인다. 대신 피해자가 평소 쓰는 나라의 IP로 들어온 공격은 덜 잡히므로, IP 평판(위협 IP 신호)을 별도로 두는 다층 구조가 필요하다.

**판정 수준(엔진 점수와 등급 기준선 적용, 개인 기준)**

| 등급(기준선) | 계정 탈취 개입 | 정상 개입 |
|---|---|---|
| 최고기밀(20) | 93.6% | 25.7% |
| 기밀(40) | 20.7% | 4.7% |
| 내부(60) | 20.7% | 4.7% |

내부 등급은 예전에는 0%였다(야간 20 + 나라 40 = 60점이 기준선 60을 넘지 못함). "두 신호가 함께면 최소 추가 인증" 규칙 추가 후의 값이다.

**민감도:** 27개 조합에서 정상 오탐 32.6~38.3%, 계정 탈취 탐지 92.9~95.7%로 차이가 작아 기본값(10건·5%·1시간)을 유지했다.

## 2. CERT 내부자 위협 데이터 r4.2 (CMU SEI, 가상 데이터)
- 가상 회사 직원 1,000명, 500일, 로그온 470,591건.
- 정답: 시나리오 1 "원래 업무 시간 외에 일하지 않던 사용자가 업무 시간 외 로그온을 시작" 30명의 내부자 기간 로그온 248건.
- 음성: 나머지 로그온 468,760건(시나리오 2·3 기간 1,583건은 시간 신호와 무관해 제외).

| | 공통 규칙(22~06시) | 개인 기준(기본값) |
|---|---|---|
| 내부자 30명 중 잡은 사람 | 25명(83.3%) | **27명(90.0%)** |
| 내부자 기간 로그온 중 걸린 비율 | 22.6% | 27.4% |
| 정상 로그온 오탐 | 4.09% | **2.25%** |
| 직원 1명당 한 달 오탐 횟수 | 1.15회 | **0.63회** |

해석: 매일 출근하는 직원 집단에서는 개인 기준이 **더 많이 잡으면서(83 → 90%) 오탐은 절반**으로 줄였다.
민감도: 비율 기준 10%·시간 폭 0시간은 30명을 다 잡지만 오탐이 한 달 4.9회로 늘고, 2%·2시간은 오탐 0.14회지만 21명만 잡는다. 기본값이 그 사이 균형점이다.
"내부자 기간 로그온 중 걸린 비율"이 낮은 것은 내부자도 기간 중 대부분은 평소 시간에 로그온하기 때문이다(사람 단위로는 대부분 잡힘).

## 한계 (보고서에 함께 적을 것)
- RBA: 노르웨이 한 서비스의 데이터, 나라 이름은 개인정보 보호를 위해 무작위화됨, 정답은 데이터셋 제작자가 붙인 것, 기록이 충분한 사용자 중 계정 탈취는 3건뿐이라 그 집단의 탐지율은 결론을 낼 수 없음.
- CERT: 가상(합성) 데이터이며 나라 정보가 없어 시간 신호만 평가 가능.
- 두 데이터 모두 우리 직원의 실제 행동이 아니다. "공개 표준 데이터로 측정한 결과"로 표현한다.
- 이 평가는 신호의 판정 규칙을 채점한 것이며, 실제 시스템(Cloudflare→Worker→엔진) 동작은 실측으로 따로 확인한다.
